# Batch-size probe: Gemini 3.5 Flash Lite, reference segmentation, two gold documents (2026-11-06)

How well does a cheap model correct the reference segmentation (`grobid.training.references.referenceSegmenter`) with 8 and 16 units per request, in both output modes? First run with the segmenting check and text-position scoring (#33).

## Setup

```bash
python -m pte_plugin_auto_annotation.probe \
  --model google/gemini-3.5-flash-lite \
  --doc 10.12775__clr.2013.008 --doc 10.5771__2699-1284-2024-3-149 \
  --variant grobid.training.references.referenceSegmenter \
  --rules-file segmenter-rules.md \
  --batches units:8,units:16 --modes all,changed --repeats 3 --retries 6 --concurrency 4
```

- Model: `gemini-3.5-flash-lite` through the editor's Google provider (paid tier), temperature 0.
- `10.12775__clr.2013.008`: reference = gold version `xzzn5j`, input = GROBID extraction `u8zbav`. The extraction has one `<bibl>` per footnote (37), the gold version one per reference (75); all 37 input units are scored, 80 edits are needed.
- `10.5771__2699-1284-2024-3-149`: reference = gold version `n67bmj`, input = GROBID extraction `yg8fvf`; 75 of 76 input units are scored (one unit's text differs in the gold version).
- Rules: the gold versions have no `editorialDecl`, so the rules were pinned with `--rules-file`: the sections "Data correction" and "Reference segmentation model" of fossil's `docs/guidelines-llm.md` and the schema `schema/grobid.training.references.referenceSegmenter.rng`, at fossil commit `7f2cb31` (about 4,400 characters).
- Scoring: elements are compared by their position in the shared text of input and gold version, so splits and merges are scored (see the plugin README, "Segmenting variants").

## Observations

- In `all` mode, the model improves both documents at both batch sizes: exact units rise from 51.4% to 64.9–67.6% (clr.2013.008) and from 74.7% to 79.1–83.1% (2699-1284-2024-3-149).
- 8 and 16 units per request are within a few points of each other in `all` mode, while repetitions of the same setting differ by up to 15 points. The run does not separate the two sizes.
- clr.2013.008, where most footnotes have to be split, is the harder case: the model's changes are mostly right (edit precision 75–80%), but it makes only about 60% of the needed ones in `all` mode.
- `changed` mode depends on how much needs to change. On clr.2013.008 the model leaves too many units alone (edit recall 29% at 16 units); on 2699-1284-2024-3-149, which needs fewer changes, it gives the best result (edit F1 86.0 at 16 units). This matches the citation-model run of the same day: `changed` mode is risky where many units need changes.
- The batch-level check accepted almost all answers: failures stay at 0–5%, and no text moved between units was rejected. No retries were needed.

## Limits

- Two documents, one model, three repetitions; the spread between repetitions is larger than the difference between the batch sizes.
- The rules were pinned from the current guide, not from the documents' own rule references (they have none), so they may differ from the rules the annotators followed.
- The probe scores the elements' positions and attributes; whether the result is valid against the segmenter schema is not checked.
